# Agent Note: 保留惯性滚动期间的底部间距

Status: implemented

[English](2026-08-15-chat-bottom-scroll-gap-guard.md) | 中文

## 问题

会话滚动容器此前把距离底部 `FOLLOW_THRESHOLD` 以内的所有位置都视为已经稳定贴底。重复的滚动事件交付，或 transcript 与编辑器尺寸变化，可能在触控板或触控惯性仍有剩余距离时写入完整的滚动高度，导致底部编辑器和最后几行内容突然向上跳动。

## 决策

`ChatView` 在仍处于贴底阈值内时记录读者实际留下的底部间距。重复滚动事件和流内容跟随布局效果会保留这段间距。尺寸变化触发的跟随逻辑只有在没有待交付的读者滚动，并且记录的间距不超过 1 像素时，才会写入滚动底部。因此读者已经进入阈值但尚未到达底部时，界面会保持当前视觉位置；真正到达底部后，流式内容继续正常跟随。

会话滚动容器和独立聊天滚动回退容器都设置 `overscroll-behavior-y: none`，阻止纵向越过客户端滚动边界继续传递 overscroll。

## 曾考虑的替代方案

**降低 `FOLLOW_THRESHOLD`。** 否决：改变所有权阈值会改变「回到底部」的行为，无法保证现有阈值内读者正在完成的底部间距得到保留。

**只使用 `overscroll-behavior-y`。** 否决：它只能控制边界滚动传递，流内容和编辑器尺寸变化仍可能触发组件主动写入 `scrollTop`，因此无法覆盖可见跳动的另一条路径。

**重新引入按设备区分的手势状态机。** 否决：observed-top ledger 已经统一归因滚轮、触控、滚动条和键盘滚动。间距保护可以在不增加输入设备监听器和手势超时的情况下处理这次写入竞态。

## 后果

读者准确位于底部时，流式内容仍会立即跟随。如果读者停在底部上方但仍处于贴底阈值内，内容增长不会继续把视图拉到底部，直到读者到达底部或使用现有的「回到底部」控件。会话边界处的纵向 overscroll 传递已关闭。

## 测试

ChatView 客户端测试覆盖了读者位于底部上方 10 像素时的重复滚动事件，以及 ResizeObserver 触发的流内容尺寸变化。ChatView 与 skeleton 两个聚焦测试套件合计 64 项通过。
